# 安全設計と運用ルール

## コードに入っている歯止め

- **dry-run 既定**：`--write` なしでは保存処理に進まない
- **二重確認**：`--write` 時は実行中に `WRITE` と入力しないと中止する
- **間隔の下限**：未承認 60 秒／承認済み 5 秒未満は起動時点でエラー
- **件数の上限**：未承認モードで `--limit` 200 超はエラー。既定の上限は 20 件と小さめ
- **編集要約の必須化**：書き込み時に `--summary` がなければエラー
- **Bot フラグの扱い**：`--approved` のときだけ Bot フラグ付き編集として保存する。未承認で Bot フラグを詐称しない

## 認証情報の扱い

- `user-config.py` と `user-password.py` は `.gitignore` 済み。コミットされていないことを push 前に必ず確認する
- BotPasswords は必要な権限だけ付けて発行する。不要になったら Wikipedia 側で失効させる
- パスワードを Issue・PR・README・チャット等に貼らない

## 運用ルール（人が守る部分）

- 合意された作業範囲（申請で説明した内容）を超えた編集をしない
- 最初は対象を少数にし、dry-run の差分を全件目視してから書く
- 誤作動や苦情があったら即停止し、会話ページ等での連絡にすぐ応答できる状態で動かす
- 深夜・混雑時間帯の大量実行は避ける。承認済みでも混雑時は間隔 20 秒以上が推奨されている
- Bot アカウントの利用者ページに停止方法・運用者を明記しておく

## やらないこと

- 未承認のままの大量・高速編集
- 内容の正確性を確認できない置換（文脈で意味が変わる語の機械的な一括置換）
- 他者の利用者ページ・会話ページへの無断編集
