# 作業計画（2026-10-29 決定）

運用者が決めた方針：**種別C（リンク修正）をメイン、種別D（誤表記修正）をサブ**とする。

## メイン：種別C ― 改名・分割に伴うリンク修正

- 対象作業：記事の改名・分割がコミュニティの合意（改名提案・分割提案）で決まったあと、`Wikipedia:Bot作業依頼`（WP:BOTREQ）に依頼されたリンク修正
- 作業方法：
  - 依頼に示された「旧名 → 新名」の対応表だけを対象にする。対応表にない置換はしない
  - リンク先だけを置き換える `--link` モードを使う（`[[旧名]]`、`[[旧名|表示名]]`、`[[旧名#節]]` のリンク先のみ。表示名・節名・本文中の文字列は変えない）
  - 節つきの対応（`旧名#節A → 新名#節B`）が依頼に含まれる場合は、対応表の文字列単位で通常モードを使う
  - 対象ページはリンク元一覧から収集し、まず dry-run で全件の差分を運用者が確認してから保存する
- 除外：利用者ページ・会話ページなど、依頼で対象とされていない名前空間。依頼文で判断できないケース（別人・同名別記事など）は置換せず、依頼ページで報告する
- 規模感：最近の同種依頼は 95〜1,618 件（2026-10-28 時点で直近3件は処理済み）。仮運用は方針の目安（40〜200回）に収まる依頼・範囲から始める

## サブ：種別D ― 明らかな誤表記の修正（半自動）

- 対象作業：文脈に左右されない、明らかな誤字・誤表記の修正のみ
- 運用方法：
  - 置換リストは固定し、項目ごとに「なぜ誤りと言えるか」「除外条件」を文書化してから使う。リストの初版は申請前に別途作り、運用者が承認した項目だけを使う
  - 各項目は初回使用前に dry-run でサンプルを確認し、誤爆（正しい表記を直してしまう）がないか運用者が全件確認する
  - 引用・固有名詞・歴史的表記など、誤りとは言えない文脈は対象外にする仕組み（除外ページ／除外パターン）を置換ごとに用意する
- 位置づけ：メイン作業の合間に小規模に行う。大量・高速では回さない

## 共通の運用条件

- 制御方式：手動制御（半自動）。Bot の起動・停止は常時運用者が行い、自動の定期実行はしない
- 稼働時期：作業依頼への対応時など、不定期。深夜・混雑時間帯の大量実行は避ける
- 編集間隔：未承認の間は 60 秒以上。承認後は 5 秒以上（混雑時は 20 秒以上を目安）
- 停止性：運用者は常時監視し、問題があれば即時停止する。利用者ページに運用者と作業内容を明記する
- 使用プログラム：Python / Pywikibot 11.9（このリポジトリのコード）
- 申請上の扱い：種別Cのうち WP:BOTREQ の案件は仮運用の事前合意が不要とされるが、種別Dは事前合意が必要。申請は両種別まとめて行い、仮運用は種別ごとに行う
